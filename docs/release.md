# Release runbook

Tags use semantic versioning: `v0.1.0`, `v0.1.1`, `v0.2.0-rc.1`. Git tags
keep the leading `v`; binary versions and Docker image tags omit it (`0.1.0`).

## Version source

`internal/version` holds `Version`, `Commit` and `Date`. Release builds inject
them with `-ldflags`:

```bash
go build -trimpath -tags embed \
  -ldflags "-s -w \
    -X github.com/pablogtrz/tablon/internal/version.Version=0.1.0 \
    -X github.com/pablogtrz/tablon/internal/version.Commit=$(git rev-parse --short HEAD) \
    -X github.com/pablogtrz/tablon/internal/version.Date=$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
  -o bin/tablond ./cmd/server
```

`tablond --version`, `tablon version`, `tablon --version` and
`/api/v1/system/status` read the same values. Docker images carry them as OCI
labels.

## Pre-release checks

```bash
go test ./...
go vet ./...
go test -race ./...
cd frontend && pnpm check && pnpm test && pnpm build && pnpm test:e2e
cd ..
go test -tags embed ./...
./scripts/bench.sh
goreleaser check
goreleaser release --snapshot --clean   # builds artifacts, does not publish
```

Run `pnpm build` before the snapshot so `go:embed all:frontend/dist` contains
the production assets. GoReleaser builds with `-tags=embed`; a binary without
the tag has no SPA and only serves the API.

## Tag and publish

1. Confirm the work is reviewed and the working tree is clean.
2. Update the M3/v0.1 checkpoint in `docs/product/build-brief.md` if needed.
3. Create and push the tag only after approval:

   ```bash
   git tag -a v0.1.0 -m "Tablon v0.1.0"
   git push origin v0.1.0
   ```

4. `.github/workflows/release.yml` runs:
   - GoReleaser for `tablond` and `tablon`;
   - Linux/amd64, Linux/arm64, macOS/amd64, macOS/arm64 and Windows/amd64
     archives;
   - `SHA256SUMS`;
   - grouped release notes from Conventional Commits;
   - a multi-arch `ghcr.io/pablogtrz/tablon:0.1.0` image with SBOM/provenance.
5. Use a prerelease tag (`v0.1.0-rc.1`) before the final tag. GoReleaser marks
   tags containing `-` as prereleases and the image job does not update
   `latest`. Image tags omit the leading `v`: `0.1.0`, `0.1`, `latest`.

## Verify the release

```bash
gh release view v0.1.0
gh release download v0.1.0 --pattern SHA256SUMS
shasum -a 256 -c SHA256SUMS     # macOS
sha256sum -c SHA256SUMS          # Linux
./tablond --version
./tablon version
curl -s http://127.0.0.1:8448/api/v1/system/status | jq .version
docker run --rm ghcr.io/pablogtrz/tablon:0.1.0 --version
docker buildx imagetools inspect ghcr.io/pablogtrz/tablon:0.1.0
```

Download and run at least one archive on macOS/Linux and inspect the Windows
binary. Check that the release contains both `tablon_*` bundle archives (server
and CLI) and `tablon-cli_*` CLI-only archives.

## Rollback

Migrate forward only. If a release is bad, restore the pre-upgrade database
backup, deploy the previous tagged image/binary and verify `/ready`. Do not
rewrite a published tag; publish a new patch release instead.

## Changelog

Release notes are generated by GoReleaser from Conventional Commits and grouped
into Features, Fixes, Performance and Other changes. Documentation, tests, chore,
CI and merge commits are filtered. No separate `CHANGELOG.md` is maintained.
